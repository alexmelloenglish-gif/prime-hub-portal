# PRIME Dependencies Ledger

**Status:** ACTIVE / release-gated  
**Owner:** PRIME Engineering  
**Policy:** audit production dependencies on every dependency change; no unreviewed force upgrades.

## 1. Critical runtime inventory

| Component | Package(s) | Runtime responsibility | Review rule |
|---|---|---|---|
| Web/runtime | `next`, `react`, `react-dom` | App Router, server rendering, API routes | Patch/minor upgrades require full build and route regressions; major upgrades require migration PR |
| Persistence | `@prisma/client`, Prisma CLI (dev) | PipelineRun, Teacher Authority, canonical records, access relations | Client and schema changes must match; migrations are never run by Vercel build |
| Authentication | `next-auth`, `@next-auth/prisma-adapter` | Google identity, session and role resolution | Preserve session/role/isolation tests; no new password/token path |
| Google integrations | `google-auth-library`, `firebase-admin` | Drive/Meet/Firestore auth and reads | Keep least privilege; validate scopes and fail-closed behavior |
| Deployment identity | `@vercel/oidc` | Runtime workload identity federation | Never replace short-lived OIDC with committed credentials |
| Media | `sharp` | Image processing | Verify Next build/runtime compatibility |
| UI | `recharts`, `lucide-react`, Tailwind packages | Dashboard charts and styling | Run dashboard contract and production build |

Direct versions and transitive resolution are authoritative in `package.json` and `package-lock.json`; this ledger intentionally does not copy stale resolved versions.

## 2. Known vulnerability baseline

A prior operational checkpoint recorded **35 npm advisories** across the dependency tree: 1 low, 10 moderate, 21 high and 3 critical. That count is historical, not a current result and not a verified production-only inventory.

The current release-specific matrix is generated by:

- Command: `npm run audit:prime-engine`
- Scope: `npm audit --omit=dev`
- Report: `artifacts/prime-dependency-audit.md`
- CI: `.github/workflows/prime-dependency-audit.yml`
- Exit policy: high/critical production advisories fail the workflow; moderate/low/info remain in the report and require an explicit disposition.

No current package is marked remediated solely because Dependabot is configured or a report workflow exists. Each fix must identify the advisory, affected direct/transitive package, fixed version/range, lockfile diff, regression CI and fresh audit result.

## 3. Disposition process

| Finding | Decision | Required mitigation/evidence |
|---|---|---|
| Critical / high with supported fix | FIX in a reviewed PR | Minimal compatible upgrade, lockfile diff, complete build and regression suite, fresh audit with zero high/critical |
| Critical / high without safe fix | OPEN / exception required | Document exploitability, exposure, compensating control, owner and expiry; cannot be silently accepted |
| Moderate / low / info | TRIAGE | Record package, advisory, reachability, fix availability and release decision |
| Transitive finding | FIX through parent dependency where possible | Avoid direct lockfile edits that are overwritten by install |
| No current finding | VERIFIED for that exact audit run only | Preserve timestamp, commit SHA and CI artifact |

## 5. Non-negotiable controls

- Never use `npm audit fix --force` as an unreviewed blanket operation.
- Never reduce severity thresholds or suppress audit exit codes to obtain a green workflow.
- Keep secrets, tokens and credential values out of report artifacts.
- Do not claim a security fix without exact package and lockfile evidence.
