## 1. Student-facing canonical structure

The student-facing Portfolio must preserve this structure and meaning:

1. **Student Learning Portfolio**
   - `[STUDENT NAME]`
   - `[PROGRAM / LEARNING TRACK] | Learning progress, class history and next-step priorities`

2. **Your Learning Snapshot**
   - Program
   - Class frequency
   - Current level
   - Target level
   - Learning focus
   - Attendance

3. **Quick Access**
   - Join My Live Class
   - My Portfolio
   - Class Materials
   - Homework
   - Lesson Calendar
   - Prime Support

4. **Estado atual de aprendizagem / Current Learning State**
   - Synthesize what the student can do now, the support required and the current focus.
   - Preserve authorized current and target levels.
   - State documentary basis and unresolved confirmation needs.
   - Do not turn isolated performance into a definitive learning claim.

5. **Forças e evidências / Strengths & Evidence**
   - Observation → Source → Pedagogical meaning → Limitation of conclusion.
   - Distinguish supported performance from independent performance.

6. **Padrões de aprendizagem / Learning Patterns**
   - Use recurring relationships supported by multiple records.
   - A single observation is an initial signal, not an established pattern.
   - Do not manufacture recurrence, frequency or causality.

7. **Prioridade pedagógica atual / Current Pedagogical Priority**
   - One principal pedagogical priority for the active cycle.
   - Include supporting evidence, why it matters now and immediate focus.
   - Separate school/external commitments from continuous language-learning objectives.

8. **Próxima ação e acompanhamento / Next Action & Follow-up**
   - Concrete operational action connected to the current learning cycle.
   - Where available: purpose, responsible participant, required material, confirmed deadline, channel/destination, status, expected evidence, feedback and result.
   - Recommendations remain proposals until teacher validation.
   - Never invent delivery, deadline, channel, completion, feedback or outcome.

9. **Memória pedagógica e próximo ciclo / Learning Memory & Next Cycle**
   - Preserve cumulative learning memory.
   - Explain what changed since the previous synthesis.
   - Separate Current State, Recent Evidence, Accumulated Memory and Next-Cycle Planning.

10. **Leitura para a família / Family Guide**
    - Brazilian Portuguese is the primary explanatory language.
    - English may remain in examples, vocabulary, activities and student language samples.
    - Use accessible language and avoid unnecessary technical jargon.
    - Do not expose internal authoring/control language as family-facing content.

11. **Attendance & Class History**
    - `Date | Class focus | Learning highlight`
    - Expand according to real records; sample rows do not limit history.

12. **Progress Tracker**
    - `Skill | Status | What this means`
    - Progress status is distinct from evidence/provenance status.

13. **Current Goals**

14. **Vocabulary Bank**
    - `Term | Meaning | Example`

15. **Grammar & Accuracy Overview**

16. **Teacher Feedback & Growth Priorities**

17. **Class Reports**
    - Each completed lesson report should identify the lesson, status, focus, evidence, language worked on, feedback and next steps.
    - Language-upgrade structure where applicable: `Original / emerging form | More natural English | Key point`.

18. **Recommended Next Steps**

19. **PRIME DIGITAL HUB footer**
    - `Your portfolio is designed to grow with every class.`

## 2. Scheduling rule — FROZEN

Scheduling resources belong to **Quick Access / Lesson Calendar**.

Scheduling information must **not automatically become a pedagogical Next Action**.

```text
SCHEDULE ≠ NEXT ACTION
```

---

## 3. PRIME Progress States — FROZEN

Exactly four learner-facing progress labels are permitted:

| State | Semantic color | Meaning |
|---|---|---|
| **Strong** | Green | Skill demonstrated consistently and with confidence |
| **Improving** | Blue | Clear, observable development |
| **Needs Focus** | Amber | Skill requires targeted attention or practice |
| **Not Assessed** | Neutral gray | Insufficient evidence to classify the skill |

### Required legacy normalization

```text
Very Strong / Secure / Established → Strong
Active Growth / Developing / Progressing → Improving
Needs Attention / Priority → Needs Focus
Insufficient evidence / unavailable assessment → Not Assessed
```

No synonyms or student-specific progress-state variants are authorized.

Progress status and evidence status are separate dimensions.

---

## 4. Attendance semantics — FROZEN

Use only the following attendance meanings:

```text
scheduled = booked / expected; not evidence of attendance
attended = lesson happened and student was present
cancelled = lesson did not happen
```

Do not count scheduled classes as attendance.  
Do not count future classes as completed.  
Do not convert a calendar entry into lesson evidence.

---

## 5. Evidence and authority integrity

Keep these conceptually distinct:

```text
Observed fact
Documented evidence
Pedagogical synthesis
Recommendation
Teacher validation / decision
```

Generated interpretation must not be presented as original observation.  
Inference must not be presented as documented fact.  
Teacher approval must not be inferred from generated text.

A level change requires explicit validation from an authorized source.

## 7. Canonical authoring instructions

### Source integrity
Use exclusively the correct student's records, authorized documents, verified class information, documented evidence and validated teacher decisions. The template provides structure; it does not provide facts. Never transport data from another student.

### Evidence integrity
Keep observation, evidence, synthesis, recommendation and teacher validation distinct.

### Progress integrity
Use only **Strong / Improving / Needs Focus / Not Assessed** and their frozen semantic colors.

### Level integrity
Current and target levels must come from authorized records. A level change requires explicit validation.

### Attendance integrity
Use **scheduled / attended / cancelled** with the meanings defined above.

### Historical integrity
Preserve accumulated learning memory and avoid duplicate representations of the same class or evidence.

### Planning integrity
Keep **Current Pedagogical Priority**, **Current Goals**, **Next Action**, **Recommended Next Steps** and **Scheduling** separate.

### Missing information
Use `unavailable`, `pending`, `unconfirmed` or `awaiting teacher validation`. Never fill missing information with plausible invention.

### Family communication
Use Brazilian Portuguese for family-facing explanations; retain English where pedagogically meaningful.

### Structural consistency
Maintain canonical section order, section meanings, tables, progress states and evidence semantics. Expand history according to real records.

```text
Portfolio = longitudinal memory and evidence

```

The Dashboard presents the registered and authorized state. It does not create new evidence or a new pedagogical decision.

## 10. Final validation checklist

Before releasing any student-facing Portfolio, verify:

- **Identity:** correct student, program, current level, target level and links.
- **Evidence:** claims supported; no invented or cross-student evidence; supported performance not mislabeled as independent mastery.
- **Pedagogy:** priority distinct from goals; Next Action concrete; recommendations identified; teacher validation not inferred; level changes separately validated.
- **Attendance:** scheduled ≠ attended; cancelled represented correctly; future classes not counted; reports correspond to completed lessons.
- **Progress Tracker:** only canonical states; no synonyms; colors semantically consistent; progress status separate from evidence status.
- **History:** accumulated memory preserved; duplicate class records avoided; longitudinal continuity intact.
- **Presentation:** all canonical sections present; placeholders replaced; internal control sections removed from student-facing copy; no fictional examples or internal authoring instructions visible.
