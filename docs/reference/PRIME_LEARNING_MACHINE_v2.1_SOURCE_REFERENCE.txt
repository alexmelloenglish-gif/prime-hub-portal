1. Purpose and Definition of the Machine
The PRIME Learning Machine is the human-readable reference implementation of the complete learning 
pipeline. It must allow a teacher to take a real lesson transcript and reproduce, step by step, every 
transformation required before a student-facing learning update becomes authoritative.
The machine is deliberately more explicit than the production software. Its job is to open the hood: every 
evidence item, interpretation, teacher decision, persistence choice, canonical record, verification result and 
student projection must be inspectable.
The machine has two equally important halves:

signals, insights, actions and candidate 
learner state.

3. Non-Negotiable Principles
Rule Meaning
Evidence before interpretation Every meaningful learning claim begins with observable 
evidence or a verified prior record.
Verbatim identity or UNKNOWN Student, teacher, date and duration must come from source 
metadata/transcript exactly. Operator memory cannot silently 
fill them.
ASR boundary Computer-generated transcript errors are not pronunciation 
evidence. Pronunciation and stable fluency require 
audio/teacher confirmation.
Attempt ≠ Evidence ≠ Assessment ≠ Progress A learner attempt can produce candidate evidence; it does not 
automatically prove stable progress.
AI proposes; teacher validates AI can organize and interpret. It cannot independently create 
final pedagogical authority.
APPROVED ≠ CANONICALIZED ≠ PROJECTED Teacher approval, canonical persistence and downstream 
publication are distinct states.

Account identity ≠ learner identity Authentication email is not pedagogical identity. The consumer

One source of canonical truth Downstream projections read verified canonical state, not 
competing email-based, Firestore, repository or legacy

Determinism is testable Same authorized inputs must produce semantically equivalent 
outputs; unexplained divergence is a specification defect.

5. Source and Identity Rules
 Copy student, teacher, date and duration verbatim from source or metadata.
 Do not replace a source label such as “PRIME DIGITAL HUB” with a presumed personal teacher name.
 Use transcript duration from metadata when available; do not estimate it.
 Record source quality once per run.
 Mark contradictory operational facts (scores, homework, access status) as UNVERIFIED unless the source 
resolves them.
 Keep account/contact information outside learner identity unless an explicit authorization relation exists.

10. Step 05 — Pedagogical Insight
Budget: 3–4 insights. Each insight answers: What does the evidence suggest may be happening in the learner’s 
development?
 Never diagnose.
 Never infer psychological states.
 Never claim causality without evidence.
 Never turn an isolated error into a stable learner profile.
 Preserve uncertainty and source limitations.
 Insights remain proposals until teacher review.

12. Step 07 — Candidate Learning State
The candidate learning state is conservative. It is not yet the CLR.
Status Meaning
ESTABLISHED Supported across multiple verified lessons or exceptionally 
explicit and teacher-validated evidence.
DEVELOPING Active area of work supported by current and/or recent 
evidence.
RECENT Demonstrated in the current lesson only.
UNKNOWN Insufficient evidence. The missing evidence should be stated.
Single-lesson rule: one lesson may populate RECENT or DEVELOPING. It must not create ESTABLISHED state by
itself.
Temporal model and status labels are complementary, not interchangeable:
Temporal layer Question answered
NOW What is currently valid enough to guide action?
RECENT What new evidence or movement has just appeared?
MEMORY What longitudinal information remains useful but is not the 
immediate state?
A status such as DEVELOPING can appear in NOW. A RECENT observation can remain in RECENT until teacher￾authorized reconciliation moves it into NOW.
13. Longitudinal Reconciliation
When a previous verified canonical state is supplied, the machine must reconcile rather than overwrite.
Reconciliation class Meaning
STILL TRUE Previous canonical belief remains supported.
NEW EVIDENCE Current lesson adds evidence without changing the state.
POSSIBLE CHANGE Evidence suggests the state may need revision; teacher decides.
SUPERSEDED Teacher authorizes replacement of a previous canonical belief.
NO EVIDENCE TO CHANGE Current lesson gives no basis to alter the prior state.
What Changed requires a baseline, new authorized evidence, the nature of the difference, and teacher 
validation. New activity alone is not automatically a change in learning state.

18. Step 13 — Atomic Canonicalization
Canonicalization receives one exact teacher-approved pedagogical payload and persists one authoritative 
canonical state. It must not silently add new pedagogical claims.
 The reviewer must be a persisted authorized teacher/admin identity in production.
 The approved payload must be stable and hashable.
 Teacher edits must be reflected before hashing.
 Canonicalization must preserve decision provenance and source references.
 Canonicalization itself does not mean downstream projection succeeded.

21. Step 16 — G4 Verified Portfolio Projection

33. Convergence Test
The golden-specimen test uses the same source lesson in independent runs.
20. Run the same untouched transcript through the same machine independently.
21. Do not expose one run’s output to the other before completion.
22. Diff artifact by artifact.
23. Classify divergence as Class A factual/structural, Class B pedagogical judgment, or Class C wording.
24. Any Class A divergence is a machine-specification defect.
25. Class B divergence beyond the tolerated set indicates a missing rubric or insufficient evidence boundary.
26. Class C wording divergence is acceptable when semantics and authority remain equivalent.
Acceptance criteria:
 Zero Class-A identity/factual divergences.
 Shared top evidence uses the same observable facts and compatible strength labels.
 Learning State statuses are semantically equivalent.
 Both gates are initially unchecked.
 Both runs include notPersisted exclusions.
 Neither run fabricates historical evidence.
 Neither run publishes before teacher approval.
 After the same teacher-approved payload, canonical hashes/projections are deterministic within the same 
schema/version.
34. Golden Specimen Protocol
The [PRIVATE PILOT LESSON] is the designated golden specimen for v2.0 reprocessing.
The next test must start again from the untouched transcript and, when longitudinal mode is intentionally 
tested, the explicitly supplied previous verified canonical state. Previous v1.0/v1.1/v2 candidate outputs must 
not be used as hidden evidence.
The reprocessing run must produce all 21 artifacts in this manual and stop for teacher validation before any 
canonical authority transition.

41. v1.5 Strict Authority Merge — Final Overrides
This section incorporates the stricter authority requirements of PRIME Learning Machine — Unified v1.5. 
Where an earlier v2.0 statement is less strict, the rules below prevail.
 A completed teacher review checklist is preparation only. CHECKLIST COMPLETE ≠ PERSISTED TEACHER 
DECISION.
 Before the persisted teacher decision and matching G3 PASS, candidate evidence, signals, insights, learning 
state, Portfolio memory, Dashboard content and student-facing copy remain proposed and not_persisted.
 proposedPersistence ACTIVE or TEMPORARY does not mean the memory is active. It becomes eligible only 
after approval, canonicalization and verification.
 APPROVE WITH EDITS freezes a new exact payload and requires a new approvedPayloadHash.
 G1/G2 eligibility is cumulative: persisted teacher decision + authorized reviewerId + resolved studentId + 
valid source lineage + frozen approved payload + matching approvedPayloadHash + scopeType/scopeKey + 
deterministic idempotencyKey.
 Canonicalization requires sourceId/sourceRef, source timestamp when available, source hash when 
computable, raw-source retention, and explicit source reliability.
 Evidence strength describes how safely an observation supports interpretation; it does not score learner 
ability.
 Evidence candidates must be atomic and traceable to sourceId/sourceSpan when available, with an explicit
boundary and immutable evidenceId.
 Without G2 commit there is no CLR. Without matching G3 PASS there is no G4/G5. Without verified G4/G5 
lineage and an active AccountLearnerRelation resolving the same studentId there is no G6. Without G6 
there is no learner-facing publication.
 APPROVED ≠ CANONICALIZED; CANONICALIZED ≠ G3 VERIFIED; G3 VERIFIED ≠ PROJECTED; PROJECTED ≠
AUTHORIZED CONSUMPTION; AUTHORIZED CONSUMPTION ≠ PUBLICATION.
 A blind transcript-only run may create candidate artifacts only and must stop at the Teacher Validation 
Gate.
 The final audit must explicitly report whether previous verified learner state was used, whether other 
outputs were consulted, whether teacher approval was present, whether canonical writes occurred, and 
whether publication occurred.
